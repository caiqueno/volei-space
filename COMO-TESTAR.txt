ANTES DE COMEÇAR
────────────────
O projeto tem um acento no caminho da pasta ("protótipo plataforma") que impede
o Next.js de rodar corretamente no Windows. Copie o projeto para um caminho sem
acento antes de qualquer coisa.

PASSO 0 — Copiar o projeto para um caminho limpo
─────────────────────────────────────────────────
1. Copie esta pasta inteira para:
   G:\Projetos\LUV\luva-platform\

   (ou qualquer caminho sem acentos, sem caracteres especiais)

2. Abra o terminal dentro da nova pasta copiada.
   Todos os comandos abaixo devem ser rodados nessa pasta.


────────────────────────────────────────────────────────────────────────────────
PASSO 1 — Configurar variáveis de ambiente
────────────────────────────────────────────────────────────────────────────────

Abra o arquivo ".env" na pasta raiz do projeto e confirme que estas linhas
estão preenchidas corretamente:

  DATABASE_URL         → string de conexão com o Supabase (já deve estar)
  DIRECT_URL           → string direta do Supabase (já deve estar)
  JWT_SECRET           → qualquer string de 32+ caracteres
  NEXT_PUBLIC_APP_URL  → http://localhost:3001

Para testar e-mails (opcional neste momento):
  SMTP_HOST  → smtp.gmail.com
  SMTP_PORT  → 587
  SMTP_USER  → seu-email@gmail.com
  SMTP_PASS  → senha de app do Google (não a senha normal)
  EMAIL_FROM → LUVA Liga <seu-email@gmail.com>

⚠️  Se não quiser configurar e-mail agora, deixe os campos SMTP em branco.
    O QR Code ainda vai aparecer na tela mesmo sem e-mail.

InfinitePay (opcional neste momento):
  INFINITEPAY_API_KEY       → deixe vazio por enquanto
  INFINITEPAY_WEBHOOK_SECRET → deixe vazio por enquanto


────────────────────────────────────────────────────────────────────────────────
PASSO 2 — Instalar dependências e criar as tabelas no banco
────────────────────────────────────────────────────────────────────────────────

Abra o terminal na pasta do projeto e rode:

  npm install

Depois, crie as novas tabelas no Supabase:

  npx prisma migrate dev --name add-candidaturas-e-inscricao

Você verá uma mensagem como "Your database is now in sync with your schema."
Isso significa que as tabelas foram criadas com sucesso.

Se aparecer erro de conexão, verifique DATABASE_URL e DIRECT_URL no .env.


────────────────────────────────────────────────────────────────────────────────
PASSO 3 — Subir o servidor
────────────────────────────────────────────────────────────────────────────────

  npm run dev

O terminal vai exibir:
  ▲ Next.js 14.x.x
  - Local: http://localhost:3001

Abra o navegador em: http://localhost:3001


────────────────────────────────────────────────────────────────────────────────
PASSO 4 — Testar o fluxo completo
────────────────────────────────────────────────────────────────────────────────

ETAPA A — Enviar uma candidatura de equipe (simula o que a Landing Page fará)
─────────────────────────────────────────────────────────────────────────────

Use o Postman, Insomnia, ou qualquer cliente HTTP. Faça:

  Método: POST
  URL:    http://localhost:3001/api/candidaturas/equipes
  Header: Content-Type: application/json
  Body:
  {
    "nome": "Volei Touchet",
    "responsavel": "João Silva",
    "email": "joao@email.com",
    "telefone": "(11) 99999-9999",
    "categoria": "MASCULINO",
    "serie": "OURO",
    "ligaId": 1,
    "diasDisponiveis": ["SEG", "QUA", "SAB"],
    "horarios": { "manha": false, "tarde": false, "noite": true },
    "quadraInfo": {
      "cobertura": true,
      "piso": "Madeira",
      "banheiro": true,
      "endereco": "Rua das Palmeiras, 100"
    }
  }

✅ Resposta esperada: status 201 com um ID de candidatura.

─────────────────────────────────────────────────────────────────────────────
ETAPA B — Ver a candidatura no painel admin
─────────────────────────────────────────────────────────────────────────────

1. Acesse: http://localhost:3001/admin/login
2. Login: use a conta de administrador do seu ambiente (tabela Admin; ADMIN_EMAIL definido). Não há credencial padrão.
3. Clique em "Candidaturas" no menu lateral
4. Você deve ver "Volei Touchet" com status PENDENTE

─────────────────────────────────────────────────────────────────────────────
ETAPA C — Aprovar a candidatura
─────────────────────────────────────────────────────────────────────────────

Na tela de Candidaturas, clique em "✓ Aprovar".

- Se INFINITEPAY_API_KEY estiver em branco: a candidatura fica como APROVADA,
  sem gerar link de pagamento. Siga para a Etapa D simulando o webhook.
- Se estiver configurada: um link de pagamento real é gerado e enviado por e-mail.

─────────────────────────────────────────────────────────────────────────────
ETAPA D — Simular o webhook de pagamento (InfinitePay)
─────────────────────────────────────────────────────────────────────────────

Este passo simula o InfinitePay confirmando que o pagamento foi realizado.

Primeiro, copie o ID da candidatura (aparece na URL ou na resposta da Etapa A).
Depois, faça esta requisição:

  Método: POST
  URL:    http://localhost:3001/api/webhooks/infinitepay
  Header: Content-Type: application/json
  Body:
  {
    "id": "fake-pagamento-001",
    "external_id": "equipe:COLE_O_ID_DA_CANDIDATURA_AQUI",
    "status": "paid",
    "amount": 25000,
    "paid_at": "2026-06-07T10:00:00Z"
  }

Substitua COLE_O_ID_DA_CANDIDATURA_AQUI pelo ID real retornado na Etapa A.

✅ Resposta esperada: { "data": { "received": true } }

O que acontece nos bastidores:
  → Equipe "Volei Touchet" é criada no banco
  → Um slug único é gerado (ex: "volei-touchet")
  → Um e-mail com o link de inscrição é enviado (se SMTP configurado)

─────────────────────────────────────────────────────────────────────────────
ETAPA E — Verificar que a equipe foi criada
─────────────────────────────────────────────────────────────────────────────

  Método: GET
  URL:    http://localhost:3001/api/equipes

Procure "Volei Touchet" na lista. Ela deve ter um campo "slug": "volei-touchet".

Também pode verificar diretamente no painel Supabase:
  https://supabase.com/dashboard → seu projeto → Table Editor → Equipe

─────────────────────────────────────────────────────────────────────────────
ETAPA F — Cadastrar um jogador (simula o atleta usando o link da equipe)
─────────────────────────────────────────────────────────────────────────────

Abra no navegador:
  http://localhost:3001/inscricao/volei-touchet

Você verá o formulário de inscrição com o nome da equipe no topo.

Preencha os campos:
  - Nome completo
  - Data de nascimento
  - CPF (formato: 000.000.000-00)
  - E-mail
  - Celular
  - Telefone de emergência
  - Posição e número de camisa (opcionais)

Clique em "Concluir cadastro e gerar QR Code".

✅ O que deve acontecer:
  → Tela de sucesso com o QR Code exibido
  → Se SMTP configurado: e-mail enviado com o QR Code em anexo
  → O QR Code pode ser salvo com print da tela

─────────────────────────────────────────────────────────────────────────────
ETAPA G — Validar o QR Code (simula a Súmula Digital lendo o QR)
─────────────────────────────────────────────────────────────────────────────

O QR Code gerado aponta para uma URL no formato:
  http://localhost:3001/api/jogadores/qr/TOKEN

Para testar diretamente:

  Método: GET
  URL:    http://localhost:3001/api/jogadores/qr/TOKEN_DO_JOGADOR

  (o token aparece na URL do QR Code)

✅ Resposta esperada: dados do jogador + equipe + foto

────────────────────────────────────────────────────────────────────────────────
PROBLEMAS COMUNS
────────────────────────────────────────────────────────────────────────────────

ERRO: Cannot find module 'styled-jsx/package.json'
  → O projeto está em um caminho com acento. Veja o PASSO 0.

ERRO: relation "CandidaturaEquipe" does not exist
  → A migração não foi rodada. Execute: npx prisma migrate dev

ERRO: Invalid login credentials (na rota /api/auth)
  → Verifique NEXT_PUBLIC_SUPABASE_URL e NEXT_PUBLIC_SUPABASE_ANON_KEY no .env

ERRO: connection refused / ECONNREFUSED (SMTP)
  → Configure corretamente ou deixe em branco para testar sem e-mail

A página /inscricao/[slug] mostra "Equipe não encontrada"
  → O webhook da Etapa D ainda não foi enviado, a equipe não foi criada
